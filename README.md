# unzip-rs（Rust + Tauri）

Windows 桌面工具，解决三个下载党日常痛点：

1. **带密码的压缩包不用到处翻密码**。平时把常用密码存进密码库（发布页看到的随手加进去），下载完成后一键解压——工具自动按密码库逐个尝试，命中的还会置顶记忆，下次更快。再也不用在「文件提供者发布页 → 聊天记录 → 便签」之间来回找密码。
2. **打包发布一站搞定**。批量把文件/目录打成加密压缩包；桌面端可选择、启用或禁用前后缀，添加自己的前后缀，并按“前缀＋数字＋后缀”命名。启用自动续号后，会从压缩包管理记录中匹配同系列最大序号，再按步长接续（数字宽度保留，Z999→Z1000）。超过阈值自动分卷，每个包混入内容唯一的 `资源说明.txt`（防网盘按 hash 秒传比对）。
3. **压缩包管理可视化**。打包记录集中保存在 `%APPDATA%\unzip-rs\pack_mapping.sqlite3`，在压缩包管理页面可以：
   - 查看所有压缩包的统计信息（大小、压缩率、分卷数）
   - 编辑多行备注，在应用设置中添加文本、下拉选项和勾选字段，自定义分类或整理状态
   - SQLite 分页浏览、实时搜索和筛选，按名称/大小/压缩率/日期排序
   - 自动保存元数据（含备份），整理游戏、文档、图片、软件等各类打包记录

技术上是个 Rust 核心库（`unzip-core`，纯逻辑无 UI）+ 命令行（`unzip-cli`）+ Tauri v2 + Vue 3 桌面应用。核心能力是**按内容魔数识别文件**，所以发布组各种伪装手法都能认出来直接解。

当前记录采用 SQLite；旧 `pack_mapping.json` 在首次使用时自动导入并保留原文件，管理页继续支持 JSON 导入和备份导出。文档入口见 [docs/README.md](docs/README.md)，保存位置与备份范围见 [数据存储说明](docs/STORAGE.md)。

## 能处理的发布组伪装手法

- **纯改后缀**：rar/zip/7z 内容改成 .jpg/.mp4/.pdf 等任意扩展名，按文件头魔数识别
- **真封面图 + 追加压缩档**（多形体）：真 jpg/png 后紧跟 rar/7z，整包识别并解出
- **完整 mp4 + 追加压缩档**：可正常播放的视频后追加 zip/rar/7z/xz（常见为「zip 装 1.exe + 尾部小档」，或加密 zip 内装 7z 分卷），自动雕出纯压缩档全链路解开；尾部命中带结构校验，真视频不会被误判
- **MP4 + ZIP64 大文件包**：支持带 ZIP64 目录、超 4GB 偏移、ZIP64 本地头和尾部附加数据的复合包，避免把游戏包当作普通视频跳过
- **SFX 自解压包**：「双击开始解压」的 exe（PE 里藏着 7z/rar/zip），与游戏启动 exe 区分识别并解压
- **垃圾前缀包**：压缩档前面垫任意字节
- **改名/带标记分卷**：`x.7z.001删`、`x.7z.002旧`、夸克 `x.7z-<哈希>.001` 均归族
- **夸克分段下载**：单档被下载器按任意字节切成 `.001/.002/.003`，归集失败时自动拼接兜底
- **套娃分卷**：压缩包内再装规范命名分卷（zip 里装 7z.001~00N），解包阶段按族归组、只解首卷自动拼接
- **内层套娃**：包里（含单层/两层子目录里）还有压缩包会继续自动解到底；两层以下的游戏数据包（存档备份/Mod 包）不碰
- **同 stem 双格式**：`a.zip` + `a.rar` 同内容只解一份，绝不覆盖旧包
- **同名嵌套**：包内顶层目录与包同名时自动折叠，不再 out/X/X
- **下载中文件**：`.qkdownloading`（夸克）/`.downloading`（百度）半成品不碰，不会打断下载；随包广告 PDF 按普通文件跳过

密码相关：加密 zip/7z/rar（含加密头）、SFX、lz4 链式套娃统一走密码库自动尝试，命中即置顶。

## 桌面界面与主题

桌面应用提供解压、打包压缩和压缩包管理三个页面，并支持自定义背景壁纸、卡片透明度和手动配色。应用设置内置以下主题预设：

- **跟随系统**：根据 Windows 当前的浅色/深色模式自动切换
- **墨黑、暖白**：低饱和的深色与浅色界面
- **灰鼠尾草、薄雾蓝、燕麦沙、灰玫瑰、暗薰衣草**：莫兰迪色系预设

壁纸支持常见图片格式（包括 AVIF），单张不超过 5 MiB。上传后可自动提取协调的界面配色，也可以手动调整颜色或重新取色。主题保存在本机 WebView localStorage；浅色和深色方案会自动调整文字与控件颜色以保持可读性。取色失败时保留已设置的壁纸并显示错误，可重新取色或改用预设、手动颜色。

### 共用工具路径

首次安装时，“应用设置 → 压缩与解压工具”默认显示随安装包提供的 7-Zip 和 UnRAR 实际路径；旧版仍为出厂默认值的路径也会更新，已有自选路径不会被覆盖。也可以手动选择其他程序并点击“保存工具路径”，下一次压缩或解压立即生效，无需重启。两个路径留空时仍会回退到内置工具。lz4 优先由内置 Rust 解码器处理，`lz4.exe` 路径只用于内置解码失败后的可选回退；正在进行的任务继续使用启动时的工具。

### 应用更新

应用启动时检查 GitHub 稳定版，发现新版本后可在“应用设置 → 应用更新”下载并安装，也支持手动检查。压缩或解压进行中不能安装更新。发布需要配置签名密钥，工作流会生成带安装包、签名和 `latest.json` 的 Release 草稿；完整配置及发布步骤见 [更新与发布](docs/UPDATES.md)。

### 自定义管理字段

点击标题栏齿轮或压缩包管理页的“管理字段”，即可添加、重命名、排序和移除字段。下拉字段的选项每行填写一个；字段定义和密码显示开关保存在当前电脑，条目的备注和字段值保存在 AppData 专用目录的集中记录中。移除字段或选项不会删除已有值，旧选项仍能显示和筛选。

### 打包命名

打包页统一使用“前缀＋数字＋后缀”命名，可以分别启用前缀和后缀，选择已有项或添加新项；关闭某一项后，该部分不参与命名及自动续号匹配。中间填写纯数字起点和递增步长，例如前缀 `G`、起点 `001`、后缀 `_正式版`、步长 `2`，得到 `G001_正式版`、`G003_正式版`。开启“自动续号”后，应用跨输出目录读取压缩包管理中的 `.7z`、`.zip`、`.rar` 记录（含分卷首卷），只匹配前后缀完全相同且中间为纯数字的包名，并从“已匹配最大序号＋步长”和手填起点中较大者开始。预览会更新，真正打包前会重新计算。旧桌面配置会转换为前缀和数字起点；CLI 的 `--name` 仍保持原行为。

旧版版本号会并入备注，引擎和 APK 标记会迁移为可配置字段，原始属性也会保留。加载旧文件时先在界面中转换，编辑保存后写入新结构。

### 压缩记录、哈希与密码

- 每成功打包一个条目就保存记录，包含压缩文件的 SHA-256；分卷分别记录文件名、字节数和 SHA-256。计算发生在单文件分卷改名之后，使用固定大小缓冲区。取消或读取失败会保留压缩文件和密码记录，并提示哪些哈希未完成。
- 解压页的“按 SHA-256 匹配记录密码”默认启用。文件大小存在候选时才计算哈希；内容命中后优先尝试对应密码，改名或移动文件仍可命中。未命中、记录不可读或密码无效时，继续使用规则和密码库。关闭后不计算解压输入的哈希。
- 分卷用待处理首卷的哈希查找密码，**不代表整组分卷已校验完整**；后续仍由解压器检查压缩包是否可用。没有哈希的旧记录仍可管理，但不能用于内容匹配。
- “应用设置 → 压缩包管理 → 显示压缩包密码”控制卡片显示，默认隐藏。此开关不加密存储，数据库及 JSON 备份中仍包含明文密码。
- 管理页直接展示集中记录，不用再逐个切换输出目录。同名但不同路径的压缩包分别保留；编辑备注只更新该条目的元数据，不覆盖同时新增的打包记录。
- 首次打开管理页会尝试导入上次使用的管理目录和打包输出目录中的旧 `pack_mapping.json`，也可点击“导入旧 JSON”选择其他文件。同路径已有记录优先保留，导入不会修改原 JSON。“导出备份”可另存完整记录。
- 集中记录使用 SQLite 事务；首次迁移遇到无效 JSON 会报错并保留原文件。集中保存失败时，会尝试在打包输出目录写入恢复 JSON，并明确告警。可用 `UNZIP_CATALOG_PATH` 为 CLI 指定独立记录位置（数据库与所指定 JSON 同目录、同名但扩展名为 `.sqlite3`）；GUI 使用自己的 AppData 目录。

完整字段、导入合并与恢复步骤见 [压缩记录格式](docs/PACK_MAPPING.md)。记录备份包含密码和字段值，但不包含主题或自定义字段定义；后者保存在本机 WebView localStorage。

### 资源管理器右键操作（Windows）

在“应用设置 → 资源管理器右键菜单”中启用入口。在文件夹中框选或多选文件后，右键选择“添加到压缩列表”或“添加到解压列表”，应用会打开相应页面；确认输出目录和参数，再点击开始。目录也能直接添加，多次添加会合并去重。

解压页可选择“仅选中文件”“仅扫描源目录”或“两者一起”；右键菜单添加的文件和目录进入选中列表。仅选中项无需填写源目录；缺少解压或打包输出目录时，点击开始会提示并打开目录选择框，选择后继续、取消则不启动。分卷请选齐同组文件。密码库、密码策略规则与解压选项分别在弹窗中配置，规则可调整顺序及启停，SHA-256 匹配位于策略规则中。失败目录旁的开关可以停用已选目录，保留路径，失败源文件留在原处。明确因密码不匹配而失败的任务可输入一个新密码单独重试，成功后新密码加入密码库。应用设置提供侧边栏，可直接跳到各设置项。右键菜单无需管理员权限；Windows 11 中通常位于“显示更多选项”，一次最多选择 100 项。应用路径改变后需在新位置重新启用；移除程序前可先在设置中关闭入口。

## 环境要求

- Windows + [Rust toolchain](https://rustup.rs/)（Rust 1.90 或更新版本）
- [Node.js](https://nodejs.org/) + npm
- 首次开发：`cd app && npm install`

## 开发模式（改代码热更新）

```powershell
cd app
npm run tauri dev
```

- 前端改动即时热更新；改了 `app/src-tauri/` 里的 Rust 会自动重编译重启
- devUrl 端口 1520（1420 被本机 Hyper-V 保留，已在配置里固定）

## 构建安装包（发布用）

```powershell
cd app
sync-bundled.bat          # 必跑：同步 assets\bundled → 打包资源（7z/UnRAR 应急组件）
npm run tauri build
```

产物：

```
app\src-tauri\target\release\bundle\nsis\unzip-rs_0.1.26101801_x64-setup.exe   ← 安装包（当前用户权限，双击即装）
app\src-tauri\target\release\unzip-app.exe                                   ← 便携版主程序
app\src-tauri\target\release\resources\                                      ← 便携版必须与 exe 同目录拷贝
```

## 命令行（不装 GUI 也能用）

```powershell
# 解压（在仓库根目录跑）
cargo run --release -p unzip-cli -- "D:\压缩包目录" -o "D:\解压输出" [--dry-run]

# 打包（每个源一个包，命名递增，超 3G 分卷 2G/个，自动密码，混入混淆 txt）
cargo run --release -p unzip-cli -- pack "D:\游戏A" "D:\游戏B" -o "D:\发布" --name G198
cargo run --release -p unzip-cli -- pack --help     # 全部参数
```

exe 在 `target\release\unzip-cli.exe`，可单独拷走；旁边放 `config.json` 可自定义 7z 路径和密码库。

## 配置

`config.json` 放在 CLI exe 旁（GUI 则在 `%APPDATA%\unzip-rs\config.json`）：

| 字段 | 说明 |
|---|---|
| `passwords` | 全局密码库，按序尝试，命中可自动置顶（`recent_first`） |
| `password_rules` | 按后缀/关键字给特定包前置专属密码（如所有 `.lz4` 先试某两个） |
| `password_strategy` | `recent_first`（命中置顶）/ `list_order` |
| `hash_match` | 是否按 SHA-256 优先尝试已记录密码，默认 `true` |
| `seven_zip` / `unrar` / `lz4` | 外部工具路径；缺省时回退 exe 旁内置组件（lz4 还有内置 Rust 解码器） |
| `output_dir` / `failed_dir` | 输出 / 失败包移入目录 |
| `product_exts` | 产物扩展名（.apk 等），只落位不解压 |
| `max_depth` | 内层解包递归深度上限 |

## 常见问题

**构建报 `failed to remove file ... unzip-app.exe` / 拒绝访问？**
应用在运行中，文件被占用。托盘退出或任务管理器结束 `unzip-app.exe` 后重新构建；命令行可用：
```powershell
taskkill /F /IM unzip-app.exe
```

**dev 模式起不来 / 端口被占？**
检查 1520 端口是否被占（`netstat -ano | findstr 1520`），杀掉占用进程即可。

**装好的应用配置在哪？密码库从哪来？**
`%APPDATA%\unzip-rs\config.json`。应急 7z 组件随应用安装，无需另装 7-Zip。

压缩包记录、备注和各分卷哈希集中保存在同目录的 `pack_mapping.sqlite3`。旧 `pack_mapping.json` 在首次迁移后保留；管理页提供旧记录导入和 JSON 备份导出。

**改了 Rust 核心后用 GUI 测试没变化？或直接 cargo 编的 GUI exe 打开白屏/「无法访问此页面」？**
GUI 是独立 cargo 工程（`app/src-tauri`），且前端资源由 **tauri CLI** 在构建时嵌入——裸 `cargo build --release` 编出的 exe **不嵌前端**，必须走 tauri 构建：
```powershell
cd app
npx tauri build --no-bundle                    # 快速：只出 exe（app\src-tauri\target\release\unzip-app.exe）
sync-bundled.bat && npm run tauri build        # 完整：exe + NSIS 安装包
```
便携版 exe 需与 `resources\` 目录同拷（内置 7z/UnRAR 应急组件）。

**分卷报「缺少 x.7z.00N / 分卷组装后校验未通过」？**
这是真缺卷：7z 首卷头部声明的元数据位置（NextHeaderOffset+32）指向全集末尾，与已有分卷合计大小一比就知道缺多少尾数据。回分享页把缺的卷/分段下完放回同目录即可，命名随意（带「删」尾标、夸克哈希名都认）。

**改了 `assets/bundled/` 里的应急组件后打包？**
重跑 `sync-bundled.bat` 再 `npm run tauri build`。

**游戏 exe 解压后消失了？**
先检查运行日志中的“跳过”、解压失败和内层解包警告，再检查实际输出目录与失败目录。失败目录启用时失败源文件会移入该目录；关闭时保留原位。成功解开的内层压缩档会被消费清理，普通游戏程序应保留。旧版曾将带视频前缀的 ZIP64 归档误判为真实媒体，当前已修复这类识别。若日志显示成功而普通程序缺失，可继续检查系统安全软件的隔离记录，并提供完整日志排查。

**压缩包解出了一层还是压缩包？**
正常：套娃结构（如 mp4→zip→SFX exe→7z 分卷）会逐层自动解到底，失败的层会留在原地并记警告，不会误删。

**打包的分卷在网盘上叫什么？**
超阈值自动产出 `G198.7z.001 / .002 …`（zip 为 `.zip.001`），下载者把同族分卷放一起用 7-Zip 打开 `.001` 即可。
