# 数据存储与 SQLite 迁移

更新日期：2026-10-16。

## 当前实现

当前正式记录采用 SQLite；旧集中 JSON 在数据库首次使用时自动导入，原文件保留。

应用与默认安装目录名称为 `unzip-rs`。配置和压缩记录位于 `%APPDATA%\unzip-rs`，主题、壁纸及其他 WebView 偏好位于 `%LOCALAPPDATA%\unzip-rs\webview`。默认输出子目录使用 `unpacked` 和 `failed`；用户显式选择的路径不会改名。

首次升级时，程序在创建窗口前将旧 `%APPDATA%\com.unzip.app` 与 `%LOCALAPPDATA%\com.unzip.app` 数据复制到新目录，原目录保留。SQLite 通过快照复制，包含 WAL 中已提交的数据；完整副本准备好后才切换到新目录，已有的新目录不会被旧数据覆盖或混入。GUI 迁移失败会停止启动并报告错误；CLI 迁移失败会报告错误并继续使用旧记录目录。内部应用标识 `com.unzip.app` 保留以兼容单实例和更新身份，它不再决定当前数据目录名称。

| 数据 | GUI 保存位置 | 保存方式 |
|---|---|---|
| 解压目录、失败目录开关、密码库、密码规则及启停、排序方式、`hash_match`、工具路径 | `%APPDATA%\unzip-rs\config.json` | 解压页开始任务前保存解压配置；工具设置通过“保存工具路径”单独保存 |
| 压缩记录、压缩密码、各产物哈希、备注、自定义字段值 | `%APPDATA%\unzip-rs\pack_mapping.sqlite3` | 每成功打包一个条目即在事务中合并保存；编辑备注按条目更新 |
| 迁移前的集中记录 | 同目录 `pack_mapping.json` | 首次迁移成功后仍保留，供核对或手动备份；不是持续更新的记录 |
| 旧 JSON 快照和锁文件 | 同目录 `pack_mapping.json.bak`、`pack_mapping.json.lock` | 旧版本可能留下；SQLite 记录不再依赖它们 |
| 自定义字段定义、旧字段迁移标记、密码显示开关 | WebView localStorage：`archive_library_fields_v1` | 修改后保存 |
| 上次成功打包的输出目录、密码模式、手动密码、模板等选项 | WebView localStorage：`pack_options` | 一批任务有成功条目时保存 |
| 壁纸图片、配色模式、预设、手动颜色、透明度等主题设置 | WebView localStorage：`unzip_wallpaper_config` | 调整主题时保存 |

localStorage 属于桌面 WebView 的本机用户数据，不属于压缩记录数据库。导出压缩记录不会一并导出界面偏好或自定义字段定义。

### CLI 与环境变量

CLI 默认从可执行文件旁读取 `config.json`；Windows 上的压缩记录默认与 GUI 共用 AppData SQLite 数据库。

| 环境变量 | 作用 |
|---|---|
| `UNZIP_CONFIG_PATH` | 覆盖核心库使用的配置文件路径；Tauri 启动时指定 GUI 配置路径 |
| `UNZIP_CATALOG_PATH` | 指定旧 JSON 的路径及 SQLite 数据库的基名；数据库与它同目录，扩展名为 `.sqlite3`；Tauri 启动时指定 GUI 路径 |
| `UNZIP_BUNDLED_DIR` | 指定内置工具的资源位置，由桌面应用启动时设置 |

仅改变 CLI 的 `UNZIP_CONFIG_PATH` 不会同时隔离 Windows AppData 记录，需要独立记录时也应设置 `UNZIP_CATALOG_PATH`。

## 备份与迁移

1. 在管理页点击“导出备份”，保存完整记录 JSON。该文件包含密码、备注和自定义字段值；定期另存此文件或在应用退出后备份 SQLite 数据库。
2. 需要备份密码库与规则时，退出应用后另外复制 `config.json`。
3. 旧输出目录中的 `pack_mapping.json` 可手动导入；已知的上次管理目录和打包目录也会在首次打开管理页时尝试导入。
4. 导入不会移动压缩文件或修改原 JSON，同路径已有集中记录优先保留。
5. 换电脑后，旧绝对路径可能失效；记录中的哈希仍可用于内容匹配，路径不会自动跟随文件移动。

旧版自动 `.bak` 只保留旧 JSON 的上一份快照，不再备份 SQLite 数据库。当前没有“一键导出全部应用设置”的功能。

## 密码可见性

“显示压缩包密码”只控制管理卡片的明文展示，默认关闭。它不加密 SQLite 数据库、JSON 备份、打包配置或日志，也不影响后端使用记录密码解压。

## SQLite 记录实现

### 为什么适合这个项目

本项目用 SQLite 保存压缩包、分卷内容哈希、密码和用户备注，并继续提供 JSON 导入导出。SQLite 官方也将桌面应用文件格式、本地记录管理列为适用场景：[选型说明](https://www.sqlite.org/whentouse.html)。

主要收益：

- 为 SHA-256 和文件大小建立索引，避免解压密码匹配时读取全部记录。
- 通过事务更新记录和分卷，统一处理增量保存及一致性。
- 管理页由 SQLite 执行搜索、字段筛选与排序，每次只返回当前页（24 条）；全库统计和匹配总数单独计算。数据库迁移版本管理仍可继续扩展。
- 内置在应用中运行，用户无需部署数据库服务。

### 体积取舍

内置 SQLite 会增加程序体积，还需计入 Rust 接口代码。SQLite 官方提供的库体积参考通常小于 1 MB，但这是通用参考，不能当作本项目 Windows 安装包的实测增量：[库体积说明](https://www.sqlite.org/footprint.html)。需要比较相同构建选项下迁移前后的 EXE 和安装包。

数据库中的用户记录保存在 AppData，不随安装包分发；记录增长影响用户数据占用，不会持续增加安装包体积。

### 迁移时应保留的行为

迁移保持以下行为：

- 自动导入现有集中 JSON，并保留原文件，事务成功后才使用数据库记录。
- 保留同名不同路径的压缩包、每个分卷的哈希、未知元数据与备注。
- 保留哈希匹配开关、失败时的密码候选回退及旧记录兼容行为。
- 保留可读的 JSON 导入、导出和备份入口。
- 不因更换存储格式改变源文件处理规则；SQLite 数据库中的密码仍是明文。

JSON 导入导出的字段与兼容规则见 [映射格式](./PACK_MAPPING.md)。
